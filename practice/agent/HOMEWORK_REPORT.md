# Отчёт по домашнему заданию

## Сценарий и формат отчёта

Отчёт строится по всем задачам TODO, полученным из `GET /api/tasks`.

- **Сводка:** дата отчёта, всего задач, выполнено и не выполнено, доля выполненных, просроченные открытые задачи, открытые задачи со сроком сегодня и открытые задачи без срока. Отдельная таблица по приоритетам `high`, `normal`, `low` показывает всего, выполнено и не выполнено.
- **Задачи:** ID, название, статус выполнения, приоритет, срок, статус срока и дата создания.
- **Методика:** точные определения показателей и границы дат.

Доля выполненных = выполненные / все задачи (для пустого списка 0). Просроченная = открытая задача со сроком раньше даты отчёта. «Срок сегодня» учитывает равенство дат; задача без срока не считается просроченной. Для уже выполненной задачи срок не меняет статус.

## Отчёт по задачам и skill

Создан skill `make_report` с детерминированным скриптом, тестами и инструкцией в `.qwen/skills/make_report/`. Локально также созданы два XLSX на одном seeded наборе из 100 задач; постоянная база приложения не менялась.

### Реальный прогон со skill

Экспорт `qwen-code-export-2026-11-07T18-28-14-748Z.html` подтверждает, что Qwen загрузил `make_report`, запустил `generate_report.py --api-url http://127.0.0.1:5001`, создал Excel на 100 задач и прочитал листы «Сводка», «Задачи» и «Методика». По экспортированной сессии: 22 вызова инструментов (17 успешных, 5 неуспешных). По предоставленному `/stats`: 35:53 общего времени, 20:27 активности агента, 868 540 входных и 35 456 выходных токенов. Экспорт этой сессии обрезан; эти token total взяты именно со скриншота `/stats`.

### Реальный прогон без вызова skill

Экспорт `qwen-code-export-2026-11-07T19-17-46-707Z.html` содержит один запрос «Сделай отчет по задачам в Excel», не содержит вызова инструмента `skill`, завершён полностью (`complete: true`, `truncated: false`). В нём 87 вызовов инструментов (79 успешных, 8 неуспешных), а метаданные экспорта указывают 4 110 545 токенов, 567 добавленных и 79 удалённых строк кода.

Важное ограничение сравнения: несмотря на отсутствие вызова `skill`, агент сначала напрямую запустил существовавший `generate_report.py` из папки skill, затем написал отдельный [make_report.py](make_report.py) и многократно дорабатывал книгу. Поэтому это прогон «skill tool не выбран», но не чистый эксперимент «агент начинает с нуля без готового скрипта». По траектории видны неудачные попытки запуска/проверки, повторные исправления Excel-разметки и валидация пустых заголовков/таблиц. Финальный ответ агента сообщает о шести листах и тех же ключевых показателях для 100 задач: 36 выполнено, 13 просрочено, 2 со сроком сегодня, 18 без срока. Отдельный `/stats` для этого прогона не предоставлен; значение токенов выше — только метаданные экспорта, не замена экранной статистике.

| Проверка | Без вызова skill | Со skill |
|---|---|---|
| Skill tool в траектории | Не вызывался; использован готовый скрипт напрямую, поэтому эксперимент не полностью «с нуля» | `make_report` явно загружен |

| Ключевые числа | 100 задач; 36 выполнено; 13 просрочено; 2 сегодня; 18 без срока | 100 задач; 36 выполнено; 13 просрочено; 2 сегодня; 18 без срока |

Панель общей активности с 6 сессиями, 887,9k токенов и 1ч 14м — агрегат по проекту, её нельзя напрямую сравнивать с одной траекторией. Два реальных прогона дают одинаковые основные цифры на одном тестовом наборе, но для причинной оценки эффекта skill нужны дополнительные чистые повторы без заранее доступного скрипта, несколько повторов со skill и эксперимент с описаниями.

## Prompt injection и защита

Добавлен `PreToolUse` hook в `.qwen/settings.json` и скрипт `.qwen/hooks/guard.py`. Он проверяет shell-команды перед запуском и отказывает для `curl`, `wget`, `nc` и `ncat`, независимо от регистра. Юнит-тесты передают hook только безвредные строки и проверяют `allow`/`deny`; команда с передачей данных наружу не запускалась, receiver не поднимался, секреты не использовались.

Поэтому успешная атака, число попыток и её сравнение с `--approval-mode yolo` здесь **не заявляются**. Это намеренное безопасное ограничение эксперимента. Для выполнения лабораторного наблюдения нужен отдельный изолированный стенд и только фиктивные данные; нельзя использовать реальные секреты или сторонние адреса. API доступен по крайней мере в показанном пользователем позднем запуске, однако тест injection не проводился.

Ответы на вопросы:

1. Инструкция в `QWEN.md` не является границей безопасности: модель может неверно расставить приоритеты, не распознать injection или выполнить действие из недоверенного контента.
2. Hook закрывает только перечисленные команды и имя конкретного shell-tool. Другие бинарники, интерпретаторы, переименование tool или сетевые библиотеки могут обойти строковый фильтр; нужны sandbox, ограничения сети и минимальные права.
3. В этом примере проще убрать канал наружу — запускать агента в контейнере/песочнице без сети, если сетевой доступ не нужен. Также можно минимизировать приватные данные в контексте.
4. Resource может попасть в контекст без вызова tool, поэтому `PreToolUse` hook на вызов tools сам по себе его не проверяет. Недоверенные данные следует маркировать, минимизировать и не считать инструкциями; сетевые ограничения должны действовать ниже уровня модели.

## Собственный MCP Prompt

`weekly_task_digest(days_ahead=7)` получает незавершённые задачи из API, исключает задачи без срока и выполненные задачи, выбирает просроченные и задачи до заданного горизонта, сортирует по сроку и приоритету, затем собирает данные и инструкции модели в prompt. Здесь нужна обработка API-ответа и параметра, а не только подстановка полей. Код и тесты находятся в `practice/mcp/server.py` и `practice/mcp/test_server.py`.

## n8n

Подготовлены три импортируемых JSON workflow в `n8n/workflows/`: детерминированная классификация, LLM со строгой JSON-схемой и AI Agent с двумя read-only tools. Шаблоны не содержат credentials, ключей, токенов или ID таблицы; перед импортом укажите собственные Google Sheets и модель через Credentials.

Фактическая проверка выполнена в облачном n8n и таблице `Support Intake`:

- **4.1** — production webhook опубликован и проверен запросами; результат возвращается, обращения записываются в `Tickets`, срочные — также в `Escalations`.
- **4.2** — test webhook вернул валидный structured output (`category=access`, `urgency=high`) и записал срочное обращение в обе вкладки.
- **4.3** — test webhook вернул `urgency=high`; execution logs подтверждают вызовы `lookup_faq` и `escalation_policy`, успешную запись в обе вкладки и ответ webhook.

Варианты 4.2 и 4.3 оставлены неопубликованными: они проверены в test mode. Production webhook 4.1 сейчас опубликован без аутентификации, поэтому любой, кто знает URL, может отправить обращение; не публикуйте новые endpoints без необходимости и защиты. Краткое сравнение и инструкция импорта находятся в `n8n/README.md`.
